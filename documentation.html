Livre Blanc Technique & Architecture Industrielle

Document technique officiel détaillant l'architecture L1, la politique monétaire stricte, les mécanismes de consensus propriétaires, et les SDK (Kotlin/Node.js) mis en œuvre par Atlas & Duc Corporation.

1. Vision & Infrastructure Souveraine

L'écosystème Nexus Core L1 a été pensé et ingénieré intégralement par Atlas & Duc Corporation. Sa conception répond à l'exigence d'une infrastructure transactionnelle africaine hautement performante, capable de s'affranchir des goulots d'étranglement des réseaux bancaires (SWIFT) sans hériter de la volatilité et des dérives spéculatives des blockchains publiques traditionnelles.

Conçu comme un réseau de confiance B2B/B2G, Nexus Core traite de manière native les contrats intelligents via la Nexus Virtual Machine (NVM), permettant la tokenisation de l'économie réelle (infrastructures agricoles, industrielles, dividendes).

1.1 L'Économie en Boucle Fermée & Le Coin Natif (1 ₳ = 1 XOF)

L'AG-COIN (₳) est le coin natif du réseau Layer-1 (et non un simple token déployé sur un réseau tiers). Son modèle économique est l'un des plus stricts de l'industrie, garanti par un adossement fiduciaire absolu :

  • Économie en Boucle Fermée (Closed-Loop) : L'AG-COIN opère dans un circuit économique hermétique et maîtrisé. Contrairement aux cryptomonnaies spéculatives, il n'y a aucun listing sur des exchanges externes (Binance, Coinbase) et aucun mécanisme de "Coin Burning" (destruction de pièces).
  • Frappe (Minting) Régulée : La création de coins sur le Mainnet ne s'effectue qu'en corrélation stricte et auditable avec un dépôt bancaire fiduciaire exactisé, verrouillé dans les réserves d'Atlas & Duc Corporation.
  • Gestion des Retraits : Lors d'une demande de retrait (virement bancaire ou Mobile Money), les coins natifs retournent dans le coffre-fort (Vault) du protocole L1. Ils ne sont jamais détruits. Ce circuit fermé garantit une stabilité structurelle imperméable aux manipulations de marché.

1.2 Architecture Multi-Couches

Pour assurer le traitement de dizaines de milliers de transactions par seconde, le réseau repose sur un déploiement serveur industriel (Node.js) orchestré par PM2 :

Couche (Layer) Implémentation Technique Technologies Employées
L0 - Routage & Infra Gossip P2P (Port 6001), Processus PM2 en fork_mode, Tunnels IPv4 (127.0.0.1). Node.js, PM2 Daemon, Cloudflare Argo Tunnels.
L1 - Consensus Core Ordonnancement des transactions, production des blocs, gestion de l'état (State). Algorithme nBFT, ECDSA (secp256k1).
L2 - Application (RPC) Endpoints d'accès (Port 9545), traitement des requêtes JSON-RPC. Express.js, NVM (Nexus Virtual Machine).

2. Algorithme de Consensus : nBFT

Nexus Core exploite le protocole propriétaire Nexus Byzantine Fault Tolerance (nBFT), un modèle hybride de DPoA (Delegated Proof of Authority) garantissant une finalité absolue et immédiate des blocs. Dès l'insertion, aucune réorganisation de chaîne (re-org) n'est possible.

nBFT Voting Flow (Golang/Pseudo-code)
// Phase 1 : Proposition par le Leader func (n *Node) ProposeBlock(txs []Transaction) { if !n.IsProposer(CurrentView) { return } block := BuildBlock(txs) n.Broadcast(PrePrepareMsg{Block: block}) } // Phase 2 & 3 : Préparation et Validation Cryptographique (Majorité 2/3) func (n *Node) OnPrepare(msg PrepareMsg) { n.PrepareVotes[msg.BlockHash]++ if n.PrepareVotes[msg.BlockHash] > (2 * TotalValidators / 3) { n.Broadcast(CommitMsg{BlockHash: msg.Block.Hash}) n.CommitBlockToState(msg.Block) // Finalité absolue immédiate } }

2.1 Nœuds Validateurs (Partenaires)

Le réseau Mainnet est soutenu par un consortium d'entités vérifiées (Institutions, Banques, Filiales Atlas & Duc). La topologie matérielle minimale requise pour opérer un nœud de validation est stricte :

  • Compute : 32 Cores / 64 Threads (Architecture x86_64 EPYC ou ARM64).
  • Mémoire (RAM) : 128 GB ECC RAM, indispensable pour le balayage rapide de l'arbre d'état (State Trie).
  • Stockage : 4 TB NVMe SSD en configuration RAID 10.

2.2 Mécanisme de Sanction (Slashing)

Pour assurer le SLA de 99.999%, le consensus intègre des pénalités asymétriques :

En cas de Double Signature (tentative de Fork volontaire par un validateur), la sanction est la confiscation immédiate de l'intégralité des fonds bloqués en garantie par le nœud et son éviction définitive du consortium (Tombstoning).

3. Cryptographie Militaire

L'architecture de sécurité d'Atlas & Duc Corporation surpasse les standards Web3, protégeant nativement les clés des portefeuilles mobiles et serveurs contre les attaques par force brute matérielle.

3.1 Dérivation de clé via Argon2id

À l'inverse des portefeuilles classiques utilisant PBKDF2 (facilement parallélisable sur ASIC), la dérivation des seeds (phrases mnémoniques) Nexus utilise Argon2id. Le coût en mémoire est défini à m=65536 (64 Mo de RAM allouée par tentative) et 4 threads, bloquant mathématiquement toute tentative de brute-force matérielle.

3.2 Signatures ECDSA (secp256k1)

Chaque transaction est chiffrée de bout en bout via la courbe elliptique secp256k1. La signature (r, s, v) intègre le Chain ID L1 (226) au sein du paramètre de récupération v, empêchant nativement le piratage par rejeu (Replay Attacks).

4. Nexus Virtual Machine (NVM)

La NVM est un environnement Turing-complet 100% compatible avec l'EVM d'Ethereum. Les partenaires peuvent déployer des contrats intelligents écrits en Solidity traitant de la logistique, des tontines, ou de l'actionnariat.

AgiDividendVault.sol
// SPDX-License-Identifier: MIT pragma solidity ^0.8.19; contract AgiDividendVault { uint256 public constant ROI_PERCENT = 10; mapping(address => uint256) public investments; function invest() external payable { require(msg.value >= 1000000, "Minimum 1 AGI (1 XOF)"); investments[msg.sender] += msg.value; } function claimDividends() external { uint256 amount = investments[msg.sender]; require(amount > 0, "Aucun investissement"); investments[msg.sender] = 0; // Prevent re-entrancy uint256 payout = amount + ((amount * ROI_PERCENT) / 100); (bool success, ) = msg.sender.call{value: payout}(""); require(success, "Transfert echoue"); } }

4.1 Modèle de Frais Fixes (Zero-Deviation Gas)

L'inconvénient majeur des réseaux publics est la variation imprévisible des frais. Nexus Core implémente un modèle mathématique bloqué au cœur du nœud : le coût d'une transaction standard (21,000 gas) est strictement verrouillé à 0.001 ₳ (soit 0.001 XOF), quelle que soit la charge du réseau. Ce modèle prédictif est essentiel pour la budgétisation des entreprises partenaires.

5. Intégration Logicielle B2B

Atlas & Duc Corporation propose des SDK complets pour interagir avec le Mainnet sans exposer vos clés privées aux requêtes HTTP brutes.

5.1 SDK Web (Node.js / Express)

backend.js
import { NexusClient, Wallet } from '@nexus-core/sdk'; const client = new NexusClient("https://rpc.agi-nexus-core.click"); const merchantWallet = new Wallet(process.env.MERCHANT_KEY, client); async function processPayment(customerAddress, amountXof) { const tx = { to: customerAddress, value: amountXof * 1000000, // Conversion en microA gasLimit: 21000 }; const receipt = await merchantWallet.sendTransaction(tx); return receipt.transactionHash; }

5.2 SDK Mobile Android (Kotlin)

Pour le développement mobile natif, le package Kotlin gère la cryptographie Argon2id locale et la signature des paquets P2P.

NexusPaymentManager.kt
import com.atlasduc.nexus.NexusClient import com.atlasduc.nexus.TransactionBuilder val client = NexusClient("https://rpc.agi-nexus-core.click") fun sendMobilePayment(destAddress: String, amountMicro: Long) { val tx = TransactionBuilder() .to(destAddress) .value(amountMicro) .gasLimit(21000) .build() // Signature matérielle asynchrone (TEE) val signedTx = tx.signWithKey(privateKeyBytes) client.sendRawTransaction(signedTx) }

5.3 Conformité KYC/AML & Auditabilité

L'infrastructure respecte les directives institutionnelles de l'UEMOA. Toutes les transactions excédant les plafonds réglementaires déclenchent des audits Anti-Money Laundering (AML) via des algorithmes de filtrage comportementaux. Les identités des utilisateurs sont liées via hachages biométriques (KYC), préservant la vie privée tout en permettant une auditabilité légale.
