Guide du Débutant : Comprendre le RPC

Parfait pour les novices de la blockchain.

Une API RPC (Remote Procedure Call) est un pont de communication. Imaginez la blockchain Nexus Core comme une immense base de données ultra-sécurisée et décentralisée. Votre application (un portefeuille mobile, un jeu Web3, ou un site e-commerce) ne peut pas lire cette base de données directement. Elle utilise donc l'API RPC pour "poser des questions" au réseau (Ex: "Quel est le solde de cette adresse ?") ou lui donner des ordres (Ex: "Envoie 100 AG-COIN à Bob").

L'architecture Atlas & Duc Corporation

La blockchain Nexus Core a été conçue de zéro (Layer-1) avec des spécificités uniques pour garantir la sécurité et la vitesse :

  • Consensus PoA (Proof of Authority) : Les blocs sont validés toutes les 2 secondes par des nœuds certifiés par l'entreprise, garantissant des frais minimes et une empreinte écologique nulle.
  • Monnaie Native : L'actif numérique natif est le AG-COIN, obligatoirement représenté par le symbole ₳.
  • Micro-divisions : 1 ₳ se divise en 1 000 000 de microA (6 décimales).
  • Cryptographie Base58 : Les adresses et les hash (identifiants de transaction) ne sont pas en hexadécimal complexe (0x...), mais encodés en Base58, plus lisibles pour l'humain.

Méthodes JSON-RPC Core

Le standard de communication avec les nœuds de la blockchain. Les requêtes s'envoient en POST avec un Content-Type application/json.

POST nexus_blockNumber

Retourne le numéro du bloc le plus récent forgé par le réseau.

const payload = {
  jsonrpc: "2.0",
  method: "nexus_blockNumber",
  params: [],
  id: 1
};

const res = await fetch('https://rpc.agi-nexus-core.click', {
  method: 'POST',
  body: JSON.stringify(payload)
});
const data = await res.json();
console.log("Dernier bloc:", parseInt(data.result, 16));
import requests

payload = {
    "jsonrpc": "2.0",
    "method": "nexus_blockNumber",
    "params": [],
    "id": 1
}
res = requests.post('https://rpc.agi-nexus-core.click', json=payload)
print("Dernier bloc:", int(res.json()['result'], 16))
Réponse attendue
{
  "jsonrpc": "2.0",
  "result": "0x1f4", // 500 en décimal
  "id": 1
}

POST nexus_getBalance

Consulte le solde d'un portefeuille. Spécificité Nexus : le nœud vous renvoie non seulement la valeur brute en `microA`, mais aussi le format texte avec le symbole `₳` et sa contrevaleur légale en `FCFA`.

Payload de requête
{
  "jsonrpc": "2.0",
  "method": "nexus_getBalance",
  "params": ["ADC6MH4qsxED6cLt..."],
  "id": 2
}
Réponse du Nœud
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "address": "ADC6MH4qsxED6cLt...",
    "microA": "5000000000", // Valeur pour les calculs (BigInt)
    "formatted": "5000.000000 ₳", // Affichage UI
    "parityXOF": "5000.000000 FCFA" // Équivalent fiat
  }
}

POST nexus_getBlockByNumber

Récupère toutes les informations d'un bloc validé sur la chaîne (Transactions, Hash Base58, Timestamp, Validateur).

  • Paramètre 1 (String/Hex) : Numéro du bloc (ex: "0x1f4", "500", ou "latest").
  • Paramètre 2 (Booléen) : true pour retourner les objets transactionnels complets, false pour n'avoir que leurs hashs.

POST nexus_getTransactionCount

Dans Nexus Core, chaque compte possède un compteur appelé Nonce. Avant d'envoyer une transaction, vous devez appeler cette méthode pour connaître le prochain Nonce valide à inclure dans votre payload de transaction.

Opération Critique (Écriture)

nexus_sendRawTransaction

Le cœur du réseau : envoyer des fonds, déployer des smart contracts ou les exécuter.

Contrairement aux requêtes de lecture, nexus_sendRawTransaction modifie l'état de la blockchain. Que vous vouliez envoyer des ₳ à un ami, déployer un contrat NCRC-20, ou interagir avec un DEX L1, tout passe par cette méthode unique qui injecte votre ordre dans la Mempool (salle d'attente des transactions) d'Atlas & Duc.

Architecture d'une Transaction Valide

Propriété Type Description technique
type String 'transfer' (défaut), 'deploy_contract', ou 'call_contract'.
from String (Base58) Votre adresse (Expéditeur).
to String (Base58) Adresse du destinataire (ou du contrat). Obligatoire sauf pour deploy_contract.
amountMicro Number/String Montant à envoyer, obligatoirement en microA. (Ex: 1 ₳ = 1000000).
feeMicro Number/String Frais de réseau offerts au validateur PoA. (0 en environnement Dev).
nonce Number Valeur exacte récupérée via nexus_getTransactionCount.
code String (JS) (Uniquement pour deploy_contract) Le code source du Smart Contract exécutable par la VM Nexus.
action Object (Uniquement pour call_contract) Les paramètres passés à la fonction du contrat. Ex: { method: "mint", params: [10] }.

Exemple 1 : Envoyer 5 AG-COIN

const transaction = {
  type: 'transfer',
  from: 'ADC6MH4qsxED6cLt...',
  to: 'ClientWallet9HHR...',
  amountMicro: 5000000, // 5 ₳ * 1,000,000
  feeMicro: 1000,       // Frais de minage
  nonce: 12           // Obtenu juste avant
};

// Dans un système réel, cet objet JSON doit être signé cryptographiquement
// avant d'être envoyé via :
// { "method": "nexus_sendRawTransaction", "params": [transaction] }

Exemple 2 : Exécuter un Smart Contract

La machine virtuelle de Nexus exécute du JavaScript sandboxé. Voici comment interagir avec un contrat L1.

const contractCallTx = {
  type: 'call_contract',
  from: 'ADC6MH4qsxED6cLt...',
  to: 'ADCC_TokenContratId99...', // ADCC = Atlas Duc Contract
  amountMicro: 0,
  feeMicro: 5000,
  nonce: 13,
  action: {
    method: 'mint',
    params: { receiver: 'UserWallet...', amount: 100 }
  }
};

WebSockets & Flux P2P Temps Réel

Écoutez la blockchain sans rafraîchir.

Pour les exchanges et dApps qui nécessitent une interface ultra-réactive, connectez-vous au serveur P2P d'Atlas & Duc sur le port 6001.

ws://p2p.agi-nexus-core.click:6001 CONNEXION WSS

Événements diffusés :

  • NEW_BLOCK Diffusé toutes les 2 secondes lorsqu'un Validateur Officiel (PoA) forge un nouveau bloc. Idéal pour confirmer le statut "Success" d'une transaction.
  • NEW_TRANSACTION Diffusé instantanément lorsqu'une transaction valide entre dans la Mempool, avant même d'être minée (statut "pending").

Codes d'Erreur & Résolution

Si votre requête échoue, l'API renvoie un objet JSON contenant la clé error selon le standard JSON-RPC 2.0.

Code Message type Explication de l'échec
-32602 Paramètre 'address' manquant Vous avez oublié de fournir les paramètres dans le tableau params: [].
-32000 Fonds insuffisants. Solde: X, Requis: Y Votre balance L1 ne couvre pas le montant envoyé + les frais (feeMicro).
-32000 Transaction désynchronisée (Nonce) Le nonce fourni dans votre transaction ne correspond pas à la valeur attendue par le Ledger.
-32005 Mempool saturée La file d'attente (max 50000 txs) est pleine. Implémentez un système de retry avec délai.
